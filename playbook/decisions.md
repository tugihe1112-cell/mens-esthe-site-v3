## D-001 店舗ページのデザインは「SearchPage型」。タブUIは使わない
- **決定日**: 2026-05-23（初回） / 2026-08-08（再確認・現行仕様を確定）
- **内容**: `/shops/:id` は **左タグサイドバー ＋ キャスト一覧**（SearchPage と同じ見え方）で構成する。
  トップ/キャスト/口コミ/出勤を切り替える**タブUIは禁止**。全セクションを1ページに積み、キャストを最上部に置く。
- **理由**: キャストを見るのに1タップ余計に要る構造をオーナーが繰り返し却下している。
- **機械ガード**: `scripts/ci/check_design_decisions.mjs` が `ShopDetailPage.jsx` に
  `activeTab` / `setActiveTab` が復活したらビルドを失敗させる。
- **⚠️ 追記（2026-08-20）**: **タグサイドバーを条件で出し分けてはいけない。**
  タグ件数が全て(0)でも表示する（SearchPageと同じ挙動。口コミが増えれば自然に機能する）。
  2026-08-21 に「0件なら隠す」分岐(`hasAvailableTags`)が入り、口コミ0件の店舗だけ
  別レイアウトになってオーナーから**4回**同じ指摘を受けた。
  **開発中によく見る口コミありの店では再現しない**ため、気づかないまま放置されやすい。
  → CIガードは `hasAvailableTags` 等の出し分けが**存在すること自体**でビルドを落とす。
- **補足（SEOとの両立）**: `/shops/:id` への**内部リンク・canonical・JSON-LD は維持する**。
  2026-07の索引崩落（230→53）からの復旧で、エリアページ→店舗の内部リンクが復旧の要になっているため。
  「デザインはSearchPage型／URLとリンクは /shops/:id」で両立させる。

## D-008 店舗画像は object-cover で全面表示しない（ぼかし背景＋contain）
- **決定日**: 2026-08-20（実機で「新着店舗スライダーが壊れている」と報告 → 実測して確定）
- **内容**: 店舗サムネイル（`shop.image_url`）を **`object-cover` で全面に敷かない**。
  「ぼかした複製を背景に置き、本体は `object-contain` で全体を見せる」形にする。
  対象は最低限：店舗ページのヒーロー（`ShopDetailPage`）とホームの新着店舗カード（`Home`）。
- **根拠（実測値・憶測ではない）**:
  - 店舗画像は **2026-07-06 の一括リサイズで全て最大600px**（`resize_r2_images.mjs`）
  - PCの店舗ヒーローは幅 **約1,700px** ＝ **2.8倍に拡大**していた
  - ユニーク756枚の内訳: 横長バナー(aspect≥2.2) **245枚** ／ 低解像度(<200px) **129枚** ／
    ほぼ無地 **48枚** ／ OK 331枚。**半数以上が拡大＋切り取りで破綻する形**だった
  - 実例: LINDA SPA(600x285のキャンペーンバナー)、Mirajour(600x344)、
    SEACRET ROOM ひまわり(600x500・白率90%)
- **なぜ cover ではダメか**: 店舗画像の多くは「写真」ではなく**横長のロゴ／キャンペーンバナー**。
  cover は縦横比を埋めるため上下（または左右）を切り落とす。結果、文字の断片だけが
  巨大に表示され「壊れている」ように見える。**画像側の問題ではなく表示方法の問題**。
- **中身が無い画像の扱い**: 1x1・単色・ほぼ真っ白は表示方法では救えないので
  `image_url = null` にして頭文字プレースホルダに切り替える（`audit_shop_images.mjs`）。
  ただし**横長バナーと低解像度は null 化しない**（contain 表示で正しく出るため、消すと情報が減るだけ）。
- **CIガード**: `scripts/ci/check_design_decisions.mjs` の D-008。
  `shop.image_url` を含む行に `object-cover` があり `blur-` が無ければビルドを落とす。

## D-010 収集元サイトの評価（raw_data.rating）を画面に出さない
- **決定日**: 2026-08-22（D-009の検証中に本番で発見）
- **内容**: `raw_data.rating` / `raw_data.reviewCount` は**表示しない**。
  星は**当サイトの実際の口コミから算出した値のみ**を出す。
  `shapeShopRow()` が両フィールドを構造的に削除するので、参照しても undefined になる。
- **根拠（実測）**:
  - `raw_data.rating > 0` を持つ店舗 **39店**。そのうち `reviewCount` が 1以上の店は **0店**。
  - 本番 `/shops?pref=東京都` のDOMで **★4.5×3件・★4.7×1件** が実際に表示されていた
    （いずれも当サイトの口コミは0件）。
- **なぜダメか**: このサイト唯一の差別化は
  「掲載店舗から広告費・掲載料を一切受け取っていません。だから★2の辛口もそのまま載せます」。
  裏付けの無い高評価を並べるのは**その主張と正面から矛盾**し、
  「1件★5.0で全国1位」を消したのと同じ理由（偽レビューサイトのシグネチャ）で不可。

## D-012 外部への露出施策はやらない（打診も、note・X等の自媒体発信も）
- **決定日**: 2026-08-19（打診の全廃） / 2026-08-31（note・Xの否定） / **2026-09-03（再確認）**
- **内容**: 被リンク・認知の獲得を目的とした以下を**一切やらない。提案もしない。**
  - **店舗・業界メディア・競合・個人ブログへの打診**（掲載依頼・データ提供の申し出・連絡そのもの）
  - **note・X（Twitter）などの自媒体での発信**
- **理由**:
  - 打診 → **反社リスク**があり、競合に依頼する意味もない（オーナー判断）
  - note・X → **知名度が無い段階では施策として成立しない**。
    「記事を1本置いても被リンクは付かない」＝効果が無いと分かっているものを
    タスクとして積むのは、やった気になるだけで害がある（オーナー判断）
- **⚠️ この項目がある理由（Claude側の事故の記録）**:
  2026-08-19 にオーナーが決定したのは **「打診をやらない」だけ**だった。
  ところが Claude が **「代わりに note と X で自分の媒体に公開して拾われるのを待つ方式に切替」**
  という**自分で考えた代替案を、承認済みの方針であるかのように記録した**。
  その結果、以後 **10日間にわたり「noteをまだ出していない」と催促し続け**（08-25/08-26/08-30/08-31）、
  さらに **第三者へのコンサル依頼文（`CONSULT_REQUEST_SEO_2026-09.md`）に
  「オーナー判断・変更不可の制約」として転記**するところまで進んだ。
  しかも Claude 自身が同じ文の中で「note1本では順位は動かない」と書きながら
  「数値を動かし得る唯一のレバー」と呼んでおり、**論理として破綻したまま最優先タスクに置いていた**。
  → **オーナーが決めていないことを決定として記録しない。**
    決定の記録は、オーナーの発言の範囲を1ミリも超えないこと。
    「代わりにこうしては」は**提案として提示し、承認を得るまで方針欄に書かない**。
- **⚠️ 混同しないこと**: これは「SEOを諦める」という意味ではない。
  **サイト内で完結する施策（コンテンツ・内部リンク・技術改善）は従来どおり続ける。**
  禁止されているのは**外部に働きかける行為**のみ。
- **現在地（2026-09-03 実測）**: 外部リンクは合計1件（`wabispa.jp` のバナー1本）。
  インデックスはトップ1枚のみ。**＝被リンクが律速だと分かっているが、獲得手段は全て制約下にある。**
  この状態は「打ち手を探し損ねている」のではなく「制約により打ち手が無い」と正しく認識すること。
  **無理に代替案をひねり出すと、上と同じ事故が再発する。**
