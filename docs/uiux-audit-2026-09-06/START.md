# メンエスマップ：新規登録を増やすための修正指示書

調査日：2026-09-06／文書作成：2026-09-07。対象：[公開サイト](https://www.mens-esthe-map.jp/)。コード基準：`4968f34`。

**これは提案と実装仕様です。今回、サイトのコード・DB・本番設定は変更していません。オーナーの確定事項として記録する文書ではありません。**

## 1. コンサルティングの結論

写真を見せる力はあります。一方、初めて来た人が「何を比較できるか」「登録すると何ができるか」を理解する情報が弱く、口コミを読んだ後も投稿への誘導が中心です。色や装飾を増やすより、**読みやすい口コミ → 登録する理由 → 入力 → メール確認 → 元の口コミへ戻る**という流れを完成させることを優先します。

現在の紺色・ピンクの世界観とcoverflowは残します。改善の中心は、細かすぎる文字、写真上で読みにくい情報、過剰な発光、繰り返す投稿バナー、登録特典の弱い表示です。登録ボタンを増やすだけでは解決しません。

現時点で登録率改善の数値は予測できません。今回GA4・実登録の完了率は取得しておらず、以下の優先順位は画面とコードからの判断です。

## 5. 全体の受入条件

- 幅360/390/768/1024/1440pxで確認。基準の画面高はスマホ844px、PC900px。横スクロールなし、入力・ボタン・本文の欠けなし。
- ホーム→公開口コミ全文→登録→確認メール→元口コミ、検索→店舗→人物→投稿→ログイン/登録→下書き復帰の2経路が成立する。
- 未登録／登録済みで閲覧権あり／登録済みで期限切れの3状態で、CTAが仕様どおり分かれる。
- メール確認は別タブ、期限切れ、使用済み、通信失敗でも回復できる。実メールの受信は検証用環境と用意済みのテストアカウントで確認し、本番の利用者へ送らない。
- 0件、初回通信エラー、追加読み込み失敗を区別する。同名人物、写真なし、長い店舗名でも表示が成立する。
- 投稿は体験欄のみ199/200/699/700字、採点コメント込みの境界、前後空白ありで、画面・検証・保存・特典表示が一致する。
- フォーカスで全操作ができ、モーダルをEscapeで閉じると開いたボタンへ戻る。スマホのキーボード表示時に入力欄と送信ボタンへスクロールできる。
- lint/buildに加え、動的SSRのホーム・店舗・人物詳細を実際に開く。build成功だけを表示正常と扱わない。
- 既存の`check_release_guards.mjs`が呼ぶガードを削除しない。単なる文字列ガードが新しい正しい文言に反応する場合は、同じ保護対象を検証する形へ更新し、検査そのものを外さない。
- UI改修でcanonical・構造化データ・公開本文のSSR・404/503境界・画像R2配信を変えない。URLは旧リンクを含め維持する。

## 6. 今回の調査範囲と限界

ブラウザでホーム、検索、店舗一覧、店舗詳細、人物詳細、登録を確認。ホーム・検索・店舗詳細・登録はスマホとPCで撮影しました。ログイン・メール確認・投稿・口コミ一覧の障害経路は主にコード確認です。匿名状態で閲覧しましたが既存の閲覧履歴が表示されるブラウザであり、完全に新しい端末の試験ではありません。

ブラウザで読んだconsoleログの範囲では一般のJavaScriptエラーは見つかりませんでした。これは全ページ・全画像・全環境の正常保証ではありません。出勤iframeの表示エラーは別途確認しています。Lighthouse、低速回線、iOS実機、実登録、メール配信成功、本番DB全件照合は未実施です。

`/shops`の「新」→「新宿」の入力は今回保持されました。F05に記載するURL同期競合はコード上の懸念として扱い、現在必ず入力が消えると断定しません。
