## C01：ブランド検索から「リストにいない」人物へ投稿しようとすると投稿先が不正になる

**優先度：P2（通常操作の一部が中断する。先に直すべき追加1件）**

### 利用者への影響

店舗欄で「TIGER GATE」を検索し、キャスト一覧の「リストにいない／新人・未登録のセラピストの口コミ」を選ぶと、リンク先が次のようになる。

```text
/post-review?shopId=g_brand_tiger_gate&customMode=true
```

`g_brand_tiger_gate` はブランドの識別子であり、実店舗のIDではない。新規入力としてこのURLを処理すると投稿先の検証に失敗し、「開いた店舗・セラピストの組み合わせを確認できませんでした」の経路へ入る。「もう一度確認」を押しても同じIDなので解消しない。「店舗を選び直す」からの復帰は可能。

既存下書きがある場合は先に下書きの選択が出る可能性がある。すべての口コミ投稿が停止する問題ではない。

### 根拠と確認方法

- **本番画面**：検索欄へ `TIGER GATE` を入力し、店舗1件・キャスト89件の画面で上記リンクをDOMから確認した。
- **本番の公開店舗一覧**：`GET /api/shops-lite` に `id=g_brand_tiger_gate` の店舗は存在しない。一方、同じ `group_id` の実店舗として `tokyo_minato_shinbashi_tiger_gate` と `tokyo_minato_toranomon_tiger_gate` が存在する。
- **実コードの模擬実行**：上記2店舗を入力にして実際の `buildBrands` を実行し、`SearchPage.jsx` から抽出した現行リンク式を評価。上記の不正URLが生成された。同じ店舗データを模擬DBにした実際の `resolveReviewTarget` は `{ ok: false, kind: 'mismatch' }` を返した。実店舗IDを渡した対照ケースは `ok: true`。
- **未実施**：本人の下書きに影響しないよう、本番の投稿フォームを開いてのエラー再現・入力・送信は行っていない。リンクと公開店舗データは本番、投稿先拒否は実関数の模擬実行、表示文言はコード確認である。

### 対象コード

| 場所 | 現在の問題・役割 |
|---|---|
| `src/pages/SearchPage.jsx:1028` | `matchingShops.length === 1` を実店舗1件とみなし、`matchingShops[0].id` を `shopId` に渡す。ここに入るのはブランド配列。 |
| `src/utils/brandGroups.js:73` | `buildBrands` は `id` をブランドキーへ変更し、実店舗IDを `shopIds`、`rooms[].id`、`primaryShopId` に保持する。 |
| `src/features/reviews/reviewTarget.js:62` | `shops.id` の実在確認。現在の拒否は正しいため、緩めない。 |
| `src/pages/PostReviewPage.jsx:705` | 投稿先照合の失敗を初期化エラーへ反映する。 |
| `src/pages/PostReviewPage.jsx:1224` | 投稿先不一致の案内・再確認・店舗選び直し。 |

### 修正方法

1. 検索結果の投稿リンクで、ブランドの `id` と実店舗の `id` を区別する。`matchingShops.length === 1` だけでは実店舗が一意とは限らない。
2. 現在の条件に対応する実在店舗IDが明示選択されている場合は、そのIDを維持する。`shopById` と現在の検索対象への所属を確認し、古い検索のIDを引き継がない。
3. 実店舗候補が1件だけなら、その `shopIds[0]` 等の実店舗IDを `shopId` に使う。`URLSearchParams` 等でURLを生成する。
4. TIGER GATEのように複数ルームが残る場合は、最小修正として `/post-review?customMode=true` へ送り、既存の店舗選択から始める。選択肢をブランド内のルームに限定するUIを追加してもよいが、今回の必須範囲ではない。代表店舗へ自動で振り分けない。
5. 投稿直前の実店舗・人物照合、下書きの選択と離脱保護を維持する。存在しないブランドIDの店舗行をDBへ追加したり、検証を外したりして回避しない。

### 完了条件

- TIGER GATEの検索結果から「リストにいない」を選んでも、ブランドIDを `shopId` に渡さず、投稿先エラーを出さずに店舗選択を始められる。
- 単独店舗ではその店舗が正しく選択される。複数ルームのうち実店舗を明示選択した場合は、その店舗を維持する。
- 複数ブランドが一致する地域検索では、勝手に先頭の店舗を投稿先へ固定しない。
- 別の店舗・人物の下書きがある場合、本人の選択なしに本文と投稿先が混ざらない。
- ブランド組立→検索リンク生成→投稿先初期化をつなぐ回帰検査を追加する。現行の誤ったブランドID代入を戻すと失敗することを確認する。既存28ガードも通す。
- 本番反映後は、下書きのない確認用セッションで実際のリンクから投稿画面を開き、店舗選択まで確認する。本文入力・実投稿はこのリンク修正の確認には不要。
